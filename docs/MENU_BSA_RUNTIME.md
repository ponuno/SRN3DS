# MENU_BSA_RUNTIME — StartMenu.swf from BSA

Status: the **read path** is implemented and validated on the installed data.
This is not a menu, a GFx movie, a frame or a draw.  It returns the stored
`Interface/StartMenu.swf` bytes in guest memory and validates the SWF container
header.  The GFx body is deliberately not decompressed or executed.

The previous census (`docs/MENU_ASSET_CLOSURE.md`) measured which archive wins
and what the movie contains.  This step makes that winner reachable from C at
runtime, with explicit refusals instead of a fake success.

## 2. Archive order and precedence (measured)

The installed `F:\Skyrim\Skyrim_default.ini` says:

```ini
[Archive]
sResourceArchiveList=Skyrim - Misc.bsa, Skyrim - Shaders.bsa, Skyrim - Textures.bsa, Skyrim - Interface.bsa, Skyrim - Animations.bsa, Skyrim - Meshes.bsa, Skyrim - Sounds.bsa
sResourceArchiveList2=Skyrim - Voices.bsa, Skyrim - VoicesExtra.bsa
```

`Update.bsa` is **not** in either INI list.  Static `TESV.exe` evidence shows it
is mounted separately **after** both lists:

* `Update.bsa\0` is at file offset `0xccc8e8`, `.rdata` VA `0x10ce0e8`
  (`.rdata` raw `0xc69800`, VA `0x106b000`).
* The pointer `0x10ce0e8` has one xref in `.text` at `0x698224`.
* The surrounding loader in `0x6981f0..0x698229` does, in order:
  1. `mov ecx,[0x1272f00]; push 0; push 0; push ecx; call 0xa3f500`
  2. `mov edx,[0x1272f0c]; push 0; push 0; push edx; call 0xa3f500`
  3. `push 0; push 0; push 0x10ce0e8; call 0xa3f040`

The two list calls consume the configured archive lists; the `Update.bsa`
literal is pushed last.  A duplicate copy of the same sequence exists at
`0x6971f0..0x697229` (the two bodies are `0x1000` apart).

Interpretation, stated with its evidence tier:

* **Measured:** the INI order above and the fact that `Update.bsa` is mounted by
  a separate call after both lists.  This is static disassembly, not a traced
  engine run.
* **Followed rule:** the last mounted archive overrides a same-path file in an
  earlier archive.  This is the rule the census used to name `Update.bsa` the
  winner; this work did not re-derive the archive manager's lookup function.
* **Measured on this install:** both archives contain
  `interface\startmenu.swf`, and the `Update.bsa` copy is the effective one.

The runtime source order is therefore fixed as:

```
0: Skyrim - Interface.bsa   (base)
1: Update.bsa               (last, override)
```

`menu_bsa_sources_init(data_dir, ...)` fills exactly those two paths.
`Update.bsa` absent is not an error; `Interface.bsa` absent is a named missing
result.

## 4. Bounded BSA reader

Implemented in `source/bsa_reader.{h,c}`.

Parsed layout (verified by `tools/skyrim/bsa.py` and re-checked here against
the shipped archives):

```
header (36)
folder records               16 * folder_count
per folder:
    u8 name length (includes NUL) + folder name
    file records             16 * folder count
file-name block              NUL-terminated base names, one per file
file data                    absolute file offsets; stored size includes prefixes
```

Handled flags:

| Flag | Meaning |
|---|---|
| `0x001` | include directory names |
| `0x002` | include file names |
| `0x004` | archive-level zlib compression |
| `0x100` | embedded full file name before each payload |

Compressed payload: `[u8 name_len + name]` when `0x100`, then `u32 unpacked
size`, then a zlib stream.  The embedded name length excludes the NUL and the
stored size counts every prefix.

Safety and bounded behaviour:

* magic, version (104/105), header offset, folder/file counts, folder-name
  length, name-block length and every record range are checked before use;
* the reader checks that folder counts sum to the header file count, that folder
  names consume exactly `total_folder_name_length`, and that the name block ends
  exactly after the last NUL;
* an internal case-insensitive index is built from the names.  The archive's
  64-bit hash fields are kept opaque; no hash algorithm was guessed;
* duplicate canonical paths are refused;
* configurable caps: folders, files, name bytes, index bytes, one stored
  payload, one unpacked payload.  Temporary folder-record and name-block
  buffers release their index-budget charge before the permanent name index and
  hash table are allocated;
* embedded-name prefix offsets are accumulated in 64-bit arithmetic and a
  payload start above the format's 32-bit file-offset field is refused, not
  truncated;
* the embedded-name-only path re-checks every length and the final name bytes
  on the second pass, so a changed archive cannot overrun the first-pass total;
* raw inflate supports stored, fixed-Huffman and dynamic-Huffman deflate blocks,
  verifies the zlib CMF/FLG header and the Adler-32, rejects preset dictionaries,
  reserved block types, bad distances, truncated streams and output overruns;
* for a compressed prefix read the whole stored entry is read into a temporary
  buffer bounded by `max_stored_bytes` (default 64 MiB).  The runtime resolver
  lowers that cap to its `budget_bytes`; this is a deliberate, documented limit,
  not streaming inflate.

Named statuses include `BSA_ERR_MAGIC`, `BSA_ERR_VERSION`, `BSA_ERR_BOUNDS`,
`BSA_ERR_COUNT`, `BSA_ERR_NAME`, `BSA_ERR_DUPLICATE`, `BSA_ERR_UNSUPPORTED`,
`BSA_ERR_FORMAT`, `BSA_ERR_TRUNCATED`, `BSA_ERR_DEFLATE` and `BSA_ERR_BUDGET`.

## 5. Runtime resolver and SWF header

Implemented in `source/menu_bsa_runtime.{h,c}`; the shared SWF header parser and
the full tag summary live in `source/menu_swf.{h,c}` (see `docs/MENU_SWF.md`).

```c
MenuBsaSources src;
menu_bsa_sources_init(data_dir, &src, reason, sizeof reason);

GuestHeap heap;
heap_create(&heap, &guest_memory, base, size);

MenuBsaResult r;
MenuBsaStatus st = menu_bsa_resolve_startmenu(
    &heap, src.source, MENU_BSA_ARCHIVE_COUNT,
    /* budget */ 1024 * 1024, &r);
if (st == MENU_BSA_OK) {
    /* r.guest_address, r.size, r.archive_name, r.swf */
    /* future GFx loader gets these bytes; this is not a draw */
    heap_free(&heap, r.guest_address);
}
```

Algorithm:

1. Open every source in order.  An absent archive is skipped; a present but
   unreadable archive is a `MENU_BSA_CORRUPT` refusal.
2. Look up the canonical path case-insensitively.  Remember the **last** source
   that contains it.  Neither source containing it is `MENU_BSA_MISSING`.
3. Read only the winning entry.  `MENU_BSA_BUDGET` is returned if the unpacked
   entry, its stored (compressed) bytes or the guest block exceed
   `budget_bytes`.
4. Read 16 prefix bytes, validate the SWF header, then allocate `heap_alloc`
   and read the full stored bytes directly into guest memory.
5. Fill the result with the guest address, size, winning archive, CRC-32 and
   SWF fields.  The caller owns the guest block.

SWF header handling:

| Signature | Result |
|---|---|
| `FWS` | accepted; version 1..32; declared total size must equal the stored size |
| `CWS` | accepted; zlib CMF/FLG is checked; body is not decompressed |
| `ZWS` | refused by name (`swf: ZWS (LZMA) compression is unsupported`) |
| other | refused by name |

A short header, a bad zlib prefix, a version outside 1..32, or an FWS
declared-size mismatch is a named refusal, never a partial success.

`MenuSwfHeader.file_bytes` is the SWF file length inside the BSA entry
(BSA-unpacked, still CWS-compressed internally).  `declared_bytes` is the
movie's own uncompressed size.  `MenuBsaResult.stored_size` separately reports
the BSA record's stored (possibly BSA-compressed) size.

Refusal mapping:

| Status | Meaning |
|---|---|
| `MENU_BSA_MISSING` | no source contains the path |
| `MENU_BSA_ACCESS` | a present archive could not be opened or read (EACCES/EBUSY/IO); never silently skipped |
| `MENU_BSA_CORRUPT` | a searched archive is present but fails a format/bounds/size check, or the winning entry fails |
| `MENU_BSA_UNSUPPORTED` | ZWS/unknown SWF signature, unsupported version |
| `MENU_BSA_BUDGET` | entry or guest allocation exceeds the caller's budget |
| `MENU_BSA_GUEST_MEMORY` | the guest heap cannot provide/back the block |
| `MENU_BSA_BAD_ARGUMENT` | missing heap/source/path/budget |

Corruption in an earlier archive is a hard refusal even when a later archive
contains the path.  A present-but-unopenable archive is also a hard refusal
(`MENU_BSA_ACCESS`), not an absent optional archive: it must not silently fall
back to `Skyrim - Interface.bsa`.

`budget_bytes` bounds the entry's unpacked size, the stored (compressed) bytes
needed for that entry, and the guest allocation.  A compressed entry whose stored
payload exceeds the caller budget is refused before a temporary allocation, so a
16-byte SWF header request cannot trigger a 64 MiB malloc.  This is a storage
budget, not a decoded-GFx budget.

## 7. What remains

This closes only the **read/validate** step.

1. **GFx draw path.**  The SWF container, tag stream, bounded display state,
   shape/glyph geometry, CPU triangle tessellation, simple Latin-1 text layout,
   A8 coverage rasterisation and CPU atlas packing are now summarized
   (`docs/MENU_SWF.md`), but a renderable display list, full sprite/movie-clip
   materialisation, AVM/AS2, input and pre-transformed batch submission do not
   exist yet.
2. **Fonts/atlas upload.**  `fonts_en.swf` / `fonts_console.swf` and
   `FontConfig.txt` still need texture upload/cache, richer shaping and the GFx
   text state.  `DefineFont3` code/advance/bounds, kerning pairs and glyph
   outlines are parsed, tessellated, rasterised and packed into caller A8
   memory; no texture or cache entry exists.
3. **NIF/DDS.**  `Logo.nif`, the menu fog particles, `logo02_d/n.dds`, fog
   textures and their shaders remain on the renderer/asset path
   (`docs/MENU_SHADER_CLOSURE.md`, `docs/TEXTURES.md`).
4. **Renderer gates.**  The GFx dynamic vertex-buffer/FVF and
   `SetTextureStageState` gaps documented in `docs/MENU_ASSET_CLOSURE.md`
   remain prerequisites for drawing the loaded movie.
5. **Engine integration beyond the SWF bytes.**  The resolver, summary,
   display/font and shape APIs are port-side asset APIs.  They are not yet
   called from a TESV resource-load stage.  The integration point is after the
   guest heap exists and before a future GFx movie creation; the result is bytes
   plus metadata/geometry, not a movie handle or a renderable display list.
