# Havok physics: SSE/x87 coverage audit

Worktree: `C:\Users\vasya\Documents\Skyrim_N3DS_wt\havok-audit` (branch
`havok-audit`, base `cbe2f9b`). This is a static/host audit only: no frame, no
hardware run and no `DevCaps` change is claimed.

## 1. Where the Havok code is

The guest image in the census container
(`E:\census_ir2\ir_container\_work\ir_container_input.bin`) is a 16-byte header
plus a raw copy of `.text`; its bytes match `E:\skyr\TESV.exe` exactly. The
container does **not** carry `.rdata`, so `hkp*` / RTTI strings are not in it.
Names were therefore read from the matching TESV PE, and all code addresses
refer to the same VA space (`0x401000`, offset `16 + VA - 0x401000`).

The audit tool is `tools/havok_audit.py`. It:

1. reads 849 Havok/Physics strings and 345 RTTI vtables from TESV
   `.rdata`/`.data`;
2. turns string/vtable references in `.text` into 1,865 directly named guest
   functions;
3. clusters them with a 4 KiB gap and treats every function starting inside a
   cluster as the Havok module address space: **15,338 functions in 72
   clusters, 3,359,560 bytes**.

The main physics block is the large cluster `0x00d0c5e0-0x00fc0c5f`; the
remaining clusters are the loosely linked serialisation/debug helpers. The full
list is committed as `docs/havok_ranges.txt` (and regenerated by the tool).
Reproduce with:

```powershell
python tools/havok_audit.py
```

`tools/havok_audit.py` also writes `build_host/havok_functions.json`, the
lifter-schema subset used below.

The old `invalid.csv` marks 226 of the 15,338 functions rejected. 27 of those
are the SSE/x87 cases above; the rest are non-SSE (`push/pop es/ss/ds`, one-byte
prefixes, `int1`, `aam`, `group5`, no-terminator blocks). A latent IR semantic
bug was also found while checking form 1: `66 0F 5B` (cvtps2dq) was implemented
as int-to-float and `0F 5B` as float-to-int, i.e. both directions were swapped.

## 3. What was implemented

### Lifter (through `tools/stage_upstream.py`, not generated files)

`staged/fpu.c`, `staged/x86.h`, `staged/lift.py` are regenerated from
`../Skyrim_Android` with new, explicit patches:

- removed `fstpnce` from `JUNK` and added `D9 D8..DF` = `ST(i) = ST(0); pop`;
- added `fbstp_store()` to `fpu.c` (18 packed BCD digits, sign bit in byte 9)
  and its declaration in `x86.h`; wired `DF /6` to it;
- added XMM forms of `paddusb`, `paddusw`, `psubusb`, `psubusw` (the existing
  code only handled the MMX forms).

The lifter already had `cvtdq2ps`, `punpck*`, `packssdw` and `movntps`.

### IR (`source/ir_decode.c`, `source/ir_exec.c`)

Decoder now accepts:

- SSE: `0F 2B` movntps/movntpd, `0F 5B` cvtdq2ps, `66 0F 60..63/67..6D`
  interleave/pack, `66 0F D8/D9/DA/DC/DD/DE` saturating add/sub/min/max;
- x87: `D9 D8..DF` fstp st(i), `DF /6` fbstp.

Interpreter now executes all of them, and fixes the `0F 5B` direction bug:
`pfx=0` int-to-float, `pfx=1` round-to-nearest float-to-int, `pfx=3`
truncating float-to-int. `movntps` is an ordinary 16-byte store (the guest is
single-threaded and non-temporal hints are not observable).

### Tests

- `tests/ir_corpus.h` / `tests/ir_aot_fixture.c` regenerated with
  `tools/ir_make_fixture.py`; the `x87ops` and `sseops` corpus functions now
  contain all new forms.
- New `tests/ir_havok_ext_smoke.c`: runs `x87ops`/`sseops` through AOT and IR
  from identical state and compares all XMM/x87/control state plus scratch and
  output memory. It does not depend on the missing D3DX pilot fixture.
- Registered as host test `ir_havok_ext` in `tools/run_host_tests.ps1`.

| `staged/lift.py` over the Havok subset | 15,238 lifted, 100 rejected; **no SSE/x87 `rt_unimpl` left** (was paddusw + fstpnce + fbstp) |
| host `ir_havok_ext` | PASS (`ok x87ops`, `ok sseops`) |

| host `tesv_slice` (hwnext2 slice + `tesv.irc`) | built and ran to a documented guest `ExitProcess(0)` after `messagebox 'Not enough memory to run application.'` — diagnostic, **not** a pass and not a frame |

The 100 remaining lifter rejects are outside the SSE/x87 scope used by Havok
math: `push/pop es/ss/ds/fs/cs` (45), `junk enter` (13), `junk les` (9),
`junk loopne/loope` (10), `int1` (7), `aam/aas/aad/aaa/daa/das` (15), one
segment override. The successfully lifted functions still contain explicit
`int` / `notrack call` / `clts` traps in unrelated helpers.

## 5. What is still open

- The container's `invalid.csv` was produced before these patches; the 226
  number is historical. The static mirror of the patched decoder reports no
  remaining SSE/x87 rejections, but regenerating the 90,900-function container
  and re-running the C decoder is the authoritative next step.
- Non-SSE Havok-reachable gaps above (`push/pop` segment, `enter`, `les`,
  `loopne`, `int1`, BCD/decimal opcodes) are not addressed here. They are
  tracked as named traps, not silent skips.
- `tesv_slice` was exercised with an existing hwnext2 generated slice, not with
  a freshly grown Havok-aware slice; the `Not enough memory` diagnostic belongs
  to that slice's allocation path and was not treated as a pass.
