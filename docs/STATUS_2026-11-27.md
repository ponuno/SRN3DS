## Fixed on this path (today)

- **`rep movsd` host-pointer invalidation** — the menu crash `0x60aa70`
  (`ecx=0x62783041`) was a `rep movs` copy landing in freed host memory when two
  ranges shared a slab page. Fixed by `n3ds_rep_movsd` in `source/rep_movs.c`;
  regression `tests/rep_movs_slab_smoke.c`. Root cause is written up in
  `docs/MENU_CRASH_HANDOFF.md`.
- **Discovery gaps** `0xb7f450`, `0xb779c0` — real constructors missing from
  `functions.json`. Added with basic-block leaders, container rebuilt
  (`E:\Skyrim_N3DS_build\ir_container_b7c\tesv.irc`).
- **IR block cap** — blocks longer than 255 instructions faulted with
  `no terminator`; now split into a synthetic fall-through `jmp`
  (`0x429872`, 333 instructions). See the handoff doc.
- **Scheduler starvation** — AOT bodies ran as native C with no yield, so one
  thread could hold the CPU for 165 s while main sat READY. `n3ds_pilot_tick_pc`
  now polls `n3ds_ir_yield_poll()` every 4096 blocks; `rep` chunks at 65536;
  watchdog gap is signed. Gap is now 0–16 ms, longest block 279 ms.
- **Menu shaders** — measured VS permutations accepted (`normal0`, `color1`,
  `abs`), exact PICA VS is no longer re-evaluated by the family matcher,
  `Clear` inside `BeginScene/EndScene` is accepted, real scissor and
  separate-alpha blend were added, NPOT render targets use POT storage with a
  logical sub-rect.
- **Bink** — real intro frames are decoded on the host (FFmpeg), tile spans are
  validated and source rects clipped to the frame; ARM still returns NULL.

## Open blockers (in order)

1. **Menu load stall**: main blocks on semaphore `0x50c`; the only runnable
   thread (9) sits in a long 64 KiB `[io] read` loop, and the hang watchdog
   currently aborts a run that may still be progressing. Worktree
   `menu-io-stall` adds IO telemetry and a watchdog that counts IO/PC progress.
2. **GFx menu draw**: once the load completes, the first GFx draw must resolve
   to a runtime PICA program. Worktree `world-runtime-paths` is adding
   `N3DS_SHADER_DRAW_TRACE` and a gate that fails when a plan exists but the
   runtime program is `none`.
3. **Menu VS residual**: 46 `menu.generic.vs` variants are selected but not
   drawable (their clip position is not the fixed CPU transform); 37 are
   skinned, 92 use `nrm`, 10 use `lrp`. See `docs/MENU_SHADER_RUNTIME.md`.
4. **World shaders**: 18 of 691 plans have runtime paths. Next unlocks are the
   normal/tangent/binormal attribute enum (9 plans), a COLOR1 carrier (4),
   translator-level `def` folding (5×10 chunks), then the software PS fallback
   for dependent texture reads (32 chunks, L).

## Update (late evening)

- **The frame pump now runs.** `GetActiveWindow` was declared twice: a stub returning 0
  in `win32_shims.c` shadowed the real one in `win32_user.c`, so WinMain took the
  "window inactive" branch (`Sleep(50)`, no `0x69cbd0`). The stub is gone and a
  visible window becomes active/foreground. After the fix: `Present=2`, GFx
  messages, and two `DrawIndexedPrimitive` from the frame loop.
- **Shader runtime wiring is proven.** `N3DS_SHADER_DRAW_TRACE` resolves every
  draw to a program. The trace exposed that 13 of 18 world paths were catalog-only
  (the core forced `draw_skinned()`); a plain fetch path now makes **23/23**
  draw paths submit, with `pica_vs_flat_draw` covering it.
- **NPOT render targets** use POT storage with a logical sub-rect (UV scaling and
  sub-rect readback), so the three Scaleform `power-of-two` refusals are gone.
- **Watchdog/IO telemetry**: `N3DS_IO_TRACE` reports bytes/paths/speed and the
  watchdog counts IR/IO progress, so a slow asset load is no longer aborted as a
  hang. The 228 s menu load is CPU-bound guest asset parsing, not disk.
- Added discovery function `0xc0e8f0` (63 blocks) and container
  `E:\Skyrim_N3DS_build\ir_container_b7d\tesv.irc`.
